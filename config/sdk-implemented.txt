# SDK functions the native runtime implements.
#
# Each name here is looked up in config/symbols/ and routed to mgs_<name> via
# the patch table, so the translated original never runs. Adding a name here
# without writing mgs_<name> is a link error, which is the intended failure:
# the table should never claim a function the runtime cannot service.
#
# Order follows the design document's phase 2: OS and DVD first because they
# block boot, then PAD, with GX logged and discarded until phase 3.

# --- OS: reporting -----------------------------------------------------------
# OSReport first, and not for convenience. The phase 1 harness compares our
# OSReport stream against Dolphin's at fixed frames; until this is native we
# have no output channel to compare.
OSReport

# --- OS: time ----------------------------------------------------------------
# The guest timebase runs at 40.5 MHz (162 MHz bus / 4). Everything the game
# schedules derives from these.
OSGetTime
OSGetTick

# --- OS: interrupts ----------------------------------------------------------
# Not real interrupt masking: guest threads are cooperative and only one runs
# at a time, so these maintain the flag the game reads back and nothing more.
OSDisableInterrupts
OSEnableInterrupts
OSRestoreInterrupts

# --- DVD --------------------------------------------------------------------
# Reads go through the worker pool; callbacks fire on the guest thread, which
# is the SDK's own contract. See runtime/dvd/dvd.h.
DVDConvertPathToEntrynum
DVDOpen
DVDFastOpen
DVDClose
# DVDReadAsync is deliberately absent: it is a MACRO in the SDK header that
# expands to DVDReadAsyncPrio, so no such function exists to patch. Listing it
# was an error the generator caught by refusing to claim an address it could
# not find.
DVDReadAsyncPrio
# The read the SYNCHRONOUS path actually uses. DVDReadPrio resolves a
# DVDFileInfo to an absolute disc offset itself and calls this, so patching
# only the by-path read left the game's loader queuing into the SDK's own
# command queue - which nothing here services - and its main thread slept in
# DVDReadPrio for the whole run. On an extracted disc the FST maps the offset
# back to a file; see mgs_disc_read_abs.
DVDReadAbsAsyncPrio
DVDGetCommandBlockStatus
# DVDGetFileInfoStatus is a real function but is not yet in the symbol map -
# a genuine gap, not a macro. Restore this line once alignment reaches it.

# --- DVD: the two-disc swap -------------------------------------------------
# MEASURED, not assumed: of every DVD function in the binary the engine calls
# five, and the disc-change path is these two. No cover polling, no drive
# state machine - the game asks which disc is present and compares. So the
# swap is answering differently. See runtime/dvd/disc_swap.c.
DVDGetCurrentDiskID
DVDCompareDiskID

# --- processor and cache control --------------------------------------------
# DolRecomp does not translate SPR access - it emits a fallback instruction and
# expects an interpreter. These are the SDK wrappers over HID0/HID2/MSR and the
# cache ops, and a boot stops inside ICFlashInvalidate two instructions in
# without them. Cache operations are honest no-ops: the host has one coherent
# memory and no guest instruction cache. See runtime/os/ppc_shims.c.
PPCMfhid0
PPCMthid0
PPCMfhid2
PPCMthid2
PPCMfmsr
PPCMtmsr
PPCHalt
PPCDisableSpeculation
PPCSetFpNonIEEEMode
ICFlashInvalidate
ICEnable
ICInvalidateRange
DCEnable
DCInvalidateRange
DCFlushRange
DCFlushRangeNoSync
DCStoreRange
L2GlobalInvalidate
LCDisable

# --- audio: deferred to phase 4 ---------------------------------------------
# The DSP bring-up waits on completion flags that hardware raises
# asynchronously, and there is no DSP here. Stubbed so the boot can reach VI;
# phase 4 replaces this with a real voice mixer. Only patchable at all because
# the patch guards now reach intra-chunk calls.
__OSInitAudioSystem
__OSStopAudioSystem

# --- the CodeWarrior runtime's block moves ----------------------------------
# Not SDK, but by far the largest single cost in the boot: a sampling profile
# puts 62.8% of the run inside memcpy and 23.5% inside __fill_mem. Nineteen
# memcpy calls in the whole boot, one of which moves 5.7 MB - the engine
# overlay, copied byte-at-a-time into the second address window, where every
# store takes the slow external-write path. See runtime/os/mem_shims.c.
memcpy
memset
__fill_mem

# The memory card, stubbed. Not phase 5's CARD emulation: without a card the
# game stops on a notice screen that needs a button press, so every headless
# run - the reproducible ones - stops before the intro movie, which is where
# the outstanding rendering faults are. Real save/load comes later as a
# pass-through to host files; see card_shims.c.
CARDInit
CARDProbeEx
CARDMountAsync
CARDCheckExAsync
CARDGetStatus
CARDMount
CARDUnmount
__CARDSync
