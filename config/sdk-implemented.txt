# SDK functions the native runtime implements.
#
# Each name here is looked up in config/symbols/ and routed to mgs_<name> via
# the patch table, so the translated original never runs. Adding a name here
# without writing mgs_<name> is a link error, which is the intended failure:
# the table should never claim a function the runtime cannot service.
#
# Order follows the design document's phase 2: OS and DVD first because they
# block boot, then PAD, with GX logged and discarded until phase 3.

# --- OS: reporting -----------------------------------------------------------
# OSReport first, and not for convenience. The phase 1 harness compares our
# OSReport stream against Dolphin's at fixed frames; until this is native we
# have no output channel to compare.
OSReport

# --- OS: time ----------------------------------------------------------------
# The guest timebase runs at 40.5 MHz (162 MHz bus / 4). Everything the game
# schedules derives from these.
OSGetTime
OSGetTick

# --- OS: interrupts ----------------------------------------------------------
# Not real interrupt masking: guest threads are cooperative and only one runs
# at a time, so these maintain the flag the game reads back and nothing more.
OSDisableInterrupts
OSEnableInterrupts
OSRestoreInterrupts

# --- DVD --------------------------------------------------------------------
# Reads go through the worker pool; callbacks fire on the guest thread, which
# is the SDK's own contract. See runtime/dvd/dvd.h.
DVDConvertPathToEntrynum
DVDOpen
DVDFastOpen
DVDClose
# DVDReadAsync is deliberately absent: it is a MACRO in the SDK header that
# expands to DVDReadAsyncPrio, so no such function exists to patch. Listing it
# was an error the generator caught by refusing to claim an address it could
# not find.
DVDReadAsyncPrio
DVDGetCommandBlockStatus
# DVDGetFileInfoStatus is a real function but is not yet in the symbol map -
# a genuine gap, not a macro. Restore this line once alignment reaches it.

# --- DVD: the two-disc swap -------------------------------------------------
# MEASURED, not assumed: of every DVD function in the binary the engine calls
# five, and the disc-change path is these two. No cover polling, no drive
# state machine - the game asks which disc is present and compares. So the
# swap is answering differently. See runtime/dvd/disc_swap.c.
DVDGetCurrentDiskID
DVDCompareDiskID
